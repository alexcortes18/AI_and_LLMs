Simple Agent With Tools - Step-by-Step Instructions

To use mainly with simple_agent_langraph_tools_clear.py

Goal
Build a LangGraph chatbot that can decide when to call tools (e.g., Tavily search), execute those tools, and then produce a natural-language answer.

Step 1. Imports and Environment
Do this:
- Import LangGraph, LangChain model wrapper, tool classes, and typing helpers.
- Load environment variables with dotenv.
- Read API keys from env.

Important to note:
- Keep secrets in .env, not hardcoded.
- For OpenAI via LangChain, use ChatOpenAI(model=..., api_key=...).


Step 2. Define State Schema
Do this:
- Create a TypedDict state with:
  messages: Annotated[list, add_messages]

Important to note:
- State is shared memory between graph nodes.
- add_messages means message updates are appended, not overwritten.


Step 3. Define Tools
Do this:
- Instantiate tool objects (e.g., TavilySearchResults(max_results=2)).
- Put tools in a list: tools = [tool].

Important to note:
- Tool objects are callable utilities, not the LLM itself.
- tools list allows adding multiple tools later.


Step 4. Bind Tools to the Model
Do this:
- model_with_tools = model.bind_tools(tools)

Important to note:
- bind_tools tells the LLM what tools exist and their input schema.
- This is what allows the model to emit tool_calls in its AIMessage.
- Without bind_tools, the model usually will not request those tools in structured form.


Step 5. Define Bot Node
Do this:
- Create bot(state) that returns:
  {"messages": [model_with_tools.invoke(state["messages"])]}

Important to note:
- The bot node is where LLM reasoning happens.
- model_with_tools (not model) is needed if you want tool-calling behavior.


Step 6. Add Tool Execution Node
Do this:
- Add a tools node using:
  ToolNode(tools=tools)

Important to note:
- ToolNode executes the requested tool calls.
- It creates ToolMessage outputs and appends them into state.
- This is runtime execution; bind_tools is only declaration to the LLM.


Step 7. Build Graph Flow
Do this:
- Add nodes: bot and tools.
- Set entry point to bot.
- Add conditional routing from bot with tools_condition.
- Add loop-back edge: tools -> bot.
- Compile graph.

Important to note:
- tools_condition routes:
  - to "tools" when tool_calls exist
  - to "__end__" when no tool call is needed
- The edge tools -> bot is critical:
  - bot asks for tool
  - tools runs tool
  - bot reads ToolMessage and produces final natural-language answer


Step 8. Run Interaction Loop
Do this:
- Use while True + graph.stream(...) for terminal chat.
- For each event, print latest assistant message content.

Important to note:
- while True controls repeated user turns.
- graph.stream handles step-by-step node execution within one turn.


bind_tools vs ToolNode (Core Difference)
- bind_tools:
  - Purpose: tell model what tools it can call.
  - Output: AIMessage may contain tool_calls.
  - Does NOT execute tools.

- ToolNode:
  - Purpose: execute the requested tool calls.
  - Output: ToolMessage with tool results.
  - Does NOT decide tool schemas for model; it only runs calls.

You need both for full tool-use behavior.


Common Mistakes
- Using model.invoke(...) in bot instead of model_with_tools.invoke(...):
  tool calling won’t trigger properly.
- Missing edge tools -> bot:
  you may see raw tool output but no final synthesized assistant answer in same run.
- Compiling graph too early:
  add all nodes/edges first, then compile.


Mental Model (Short)
- LLM (with bind_tools) decides WHETHER and WHICH tool to call.
- ToolNode performs the actual tool call.
- Graph controls WHEN each step runs and how state moves.
